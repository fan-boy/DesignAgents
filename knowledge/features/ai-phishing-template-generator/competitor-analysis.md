### Feature context
AI Phishing Template Generator (`ai-phishing-template-generator`) lets a security analyst generate a phishing simulation template from a free-text scenario or an uploaded real email, with tone/layout/link-structure preservation, text-based sensitive-data redaction, safe-URL rewriting, Easy/Medium/Hard difficulty, WYSIWYG editing, and desktop/mobile preview, targeting ~10s generation time. Per prd-research, key open risks are: no retention policy for uploaded raw email content, no defined template library behavior, and (per stakeholder decision) redaction is text-only with no image-content handling in v1.

### Competitors reviewed
Selected per the registry's feature-type table for "Phishing / spear phishing simulation": **KnowBe4**, **Hoxhunt**, **Cofense**. All three are direct SAT/phishing-simulation competitors and are the only registry entries with a documented generative or real-email-to-template creation path. CybSafe, SoSafe, Proofpoint, Mimecast, Ninjio, Curricula, and Doppel were excluded — none has a documented AI-template-generation or real-email-ingestion capability, and several are explicitly out of scope for this comparison type per the registry's "when NOT to compare" guidance (e.g., Proofpoint/Mimecast are not primarily SAT products; Doppel is a different category). Confidence is **medium**: findings are drawn from vendor marketing and support pages, not hands-on product trials, and one source (a Hoxhunt-authored competitor comparison blog) is explicitly vendor-biased and flagged below.

### Workflow comparison

**KnowBe4 — AIDA Template Generation Agent** (closest analog to "Describe a Scenario")
- Entry point: part of KnowBe4's AIDA suite of autonomous AI agents inside the phishing simulation setup flow.
- Setup friction: admin specifies simulation parameters — difficulty level and/or specific Social Engineering Indicators aligned to the NIST Phish Scale Framework — rather than a free-text prompt.
- Core flow: admin sets parameters → Template Generation Agent autonomously constructs a realistic template reflecting current attack vectors → a separate Recommended Landing Pages Agent auto-pairs a contextually appropriate landing page. A distinct Callback Template Generation Agent handles callback-phishing (vishing-adjacent) templates specifically.
- Feedback/review: KnowBe4's own product pages do not describe an explicit review or edit step between generation and deployment — templates are framed as ready to use once generated. *(Inference: this may exist but isn't marketed; treat as an observed gap in the public-facing description, not confirmed absence.)*
- Difficulty control: explicit, framework-anchored (NIST Phish Scale Social Engineering Indicators), not just a generic Easy/Medium/Hard label.
- AI framing: positioned as "autonomous agents," consistent with KnowBe4's broader 2026 AIDA Orchestration push toward agentic, self-managing human risk programs.

**Hoxhunt** (closest analog to difficulty tiering)
- Entry point: phishing simulation configuration within Hoxhunt's adaptive training flow.
- Core flow: rather than a one-time generation choice, Hoxhunt continuously adjusts simulation difficulty per user based on ongoing performance — harder simulations to users who consistently report correctly, easier ones to those still learning.
- Difficulty control: a four-tier scale (easy to expert), plus a "Spicy Mode" that adds challenge on top for advanced users. This is algorithmic and per-user/adaptive rather than a one-time author-selected setting per template.
- AI content generation: Hoxhunt states it uses AI to generate simulation content that matches current attack sophistication (avoiding the outdated "spelling errors and clumsy formatting" tells), but does not describe a scenario-prompt or real-email-upload creation flow analogous to Dune's two modes.
- Note on source bias: a Hoxhunt-authored blog post comparing competitors characterizes KnowBe4 as relying on a static content library "rather than AI generation" — this conflicts with KnowBe4's own product pages describing AIDA's generative Template Generation Agent. Treat the Hoxhunt blog's characterization of competitors as vendor-biased and lower-confidence; KnowBe4's own documentation is the higher-confidence source here.

**Cofense** (closest analog to "Copy an Email")
- Entry point: tied to Cofense's Reporter-button and Triage ecosystem — employees report suspicious emails, which feed into Cofense Triage for analyst review.
- Core flow: real, reported phishing emails that reach Cofense's analysts can be converted into simulation content, rather than an admin directly uploading an arbitrary `.eml` themselves as the trigger. This is a closed-loop, analyst-mediated pipeline (report → triage → simulation), not a self-serve "upload an email, get a template in 10 seconds" flow.
- Library model: Cofense leans heavily on a large pre-built template library (1,500+ templates, 36 languages) with automation for scheduling and smart suggestions based on historical results and active threats, rather than freeform generative authoring.
- No documented direct-upload-to-template generation path comparable to Dune's "Copy an Email" mode — Cofense's real-email path runs through its own reporting/triage infrastructure, not analyst-initiated upload.

### Patterns worth adopting
- **Framework-anchored difficulty controls (KnowBe4).** Anchoring difficulty to a named, credible framework (NIST Phish Scale Social Engineering Indicators) gives admins a defensible, explainable reason for a template's sophistication level, rather than an opaque Easy/Medium/Hard label alone. Dune's difficulty tiers could reference what specifically changes (urgency cues, visual polish, pretext depth — already specified in the PRD) directly in the UI, the way KnowBe4 names indicators, so the label isn't just decorative.
- **Auto-pairing complementary agent output (KnowBe4).** The Recommended Landing Pages Agent auto-suggesting a contextually matched landing page alongside a generated template is a useful precedent for the deploy-time seam between this feature and the campaign launcher — Dune could similarly auto-suggest campaign or landing-page defaults based on the template's category/difficulty at hand-off, though that is explicitly out of scope for this feature per the PRD.
- **Threat/result-informed suggestions (Cofense).** Cofense's use of historical simulation results and active-threat data to suggest what to run next is a differentiation cue: Dune's risk-scoring integration (already an open question in prd-research) could similarly inform which scenario categories or difficulty levels are suggested first when an analyst starts a new template.

### Anti-patterns to avoid
- **No visible review/edit gate before use (KnowBe4, as publicly described).** If AIDA-generated templates go from generation straight to deployment-ready with no documented review step, that's a trust risk for any customer relying on marketing claims alone — an admin could deploy a poorly-generated or miscalibrated template without realizing review was optional rather than required. Dune's PRD already specifies WYSIWYG editing and desktop/mobile preview as steps every generated template passes through — that should be treated as a differentiator to state plainly, not something to weaken toward KnowBe4's leaner-looking flow.
- **Analyst-mediated-only real-email pipeline (Cofense).** Requiring real phishing emails to pass through a reporting/triage/analyst pipeline before becoming simulation content is safer from a data-handling standpoint but adds real friction and centralizes the work Dune's PRD is explicitly trying to decentralize away from "a central content team." Don't copy Cofense's model here — but do note that Cofense's more cautious posture toward real-email content is aligned with the retention/handling concerns already flagged as unresolved in `open-questions.md`, and worth revisiting if that question resolves toward stricter handling.
- **Opaque per-user adaptive difficulty with no author control (Hoxhunt).** Hoxhunt's fully algorithmic, per-user difficulty adjustment removes the analyst's ability to author a specific difficulty for a specific scenario — appropriate for Hoxhunt's continuous-training model, but not a fit for Dune's PRD, which specifies analyst-selected difficulty per template. Don't blur these two models; Dune's approach (analyst sets difficulty, explicit Regenerate to change it) is a deliberate, different design point and should be described as such rather than implied to be less sophisticated.

### Differentiation opportunities
- **Self-serve speed vs. Cofense's analyst-mediated pipeline.** None of the three competitors documented offer a self-serve "upload a real email, get a usable draft template in ~10 seconds" flow — Cofense's closest equivalent runs through an analyst/triage pipeline. Dune's PRD goal of eliminating dependency on a central content team is a real, findable gap in the competitive set, not just positioning language.
- **Named difficulty mechanics vs. opaque labels.** Neither Cofense nor Hoxhunt exposes an author-facing explanation of what a difficulty level actually changes about the generated content (Hoxhunt's is algorithmic and per-user, not per-template; Cofense doesn't appear to expose a generative difficulty control at all). Dune's PRD already defines what Easy/Medium/Hard changes (urgency language, visual polish, pretext depth) — surfacing that explanation in the UI, the way KnowBe4 anchors to NIST Phish Scale indicators, would differentiate on transparency.
- **Explicit edit/preview step as a trust signal.** Given KnowBe4's public materials don't describe a review step and Cofense's model routes real-email content through internal review by design, Dune can position its WYSIWYG edit + desktop/mobile preview step as a deliberate trust and quality gate every generated template passes through — worth stating explicitly in the product rather than treating it as an incidental capability.

### Implications for design
- Difficulty control UI should expose *what* changes at each tier (echoing the PRD's own Easy/Medium/Hard behavior table), not just present three unexplained labels — this out-differentiates the closest comparable competitor pattern (KnowBe4's framework-anchored indicators) without requiring Dune to adopt NIST Phish Scale terminology directly.
- Because no competitor offers a true self-serve real-email-upload-to-template flow, there's no existing UX convention to lean on for "Copy an Email" — this flow should be designed from Dune's own upload/sanitization patterns (per prd-research's note to reuse `aep-library`-adjacent conventions) rather than assumed to follow a known competitor pattern.
- The WYSIWYG edit + preview step should be framed in the UI as a deliberate quality/trust checkpoint (e.g., a labeled step, not just an editor that happens to open after generation), since this is a point of differentiation from what competitors publicly describe.
- Given Cofense's more conservative, analyst-mediated posture toward real-email content, design-strategist should keep in view that the unresolved retention/handling question for uploaded `.eml` content (see `open-questions.md`) is not just an internal compliance question — it's a point where a competitor has already made a more cautious choice for reasons Dune should be prepared to answer for.

- Cofense's real-email-to-template pipeline is inferred from descriptions of its Reporter/Triage ecosystem and template library messaging; no source explicitly documents a named feature equivalent to "upload an .eml, get a template," so this is a moderate-confidence inference, not a confirmed feature match.
- No competitor source discusses image-embedded sensitive-data redaction, workspace isolation of uploaded content, or RBAC granularity for template creation versus deployment in enough detail to compare directly against Dune's PRD on those dimensions.
